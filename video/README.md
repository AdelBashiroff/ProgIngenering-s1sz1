# Задача 4. Детекция объектов на видео (YOLO)

Часть серии заданий по дисциплине «Программная инженерия» (семестр 1).
Тип задачи: **обработка видео**. Фреймворк: **PyTorch** (библиотека Ultralytics YOLO).

## Техническое задание

| | |
|---|---|
| **Цель** | Находить и подписывать объекты на видео |
| **Вход** | Видеофайл (mp4, avi, mov), любое разрешение |
| **Выход** | Видео с рамками и подписями классов, таблица всех детекций (`*_detections.csv`), сводка по классам и скорости (`*_summary.json`) |
| **Классы** | 80 классов набора COCO (person, car, bus, dog, ...) |
| **Ограничения** | Готовая модель без дообучения; локальный запуск (CPU / Apple Silicon MPS / CUDA) |
| **Критерий качества** | AP@[.5:.95] на COCO val2017 не ниже 0.30 (для модели nano), обработка не медленнее 5 кадров/с на ноутбуке |

## Модель

**YOLO11** (You Only Look Once, Ultralytics) — одностадийный детектор: одна свёрточная нейросеть за один проход по кадру предсказывает рамки объектов, их классы и уверенность, затем лишние пересекающиеся рамки удаляются алгоритмом NMS. Благодаря этому YOLO быстрее двухстадийных детекторов вроде Faster R-CNN, что важно для видео.

Используются предобученные на COCO веса разных размеров:

| Модель | Параметров | Особенность |
|---|---|---|
| `yolo11n.pt` (по умолчанию) | 2.6 млн | Самая быстрая, подходит для обработки видео на ноутбуке |
| `yolo11s.pt` | 9.5 млн | Точнее, медленнее |

Веса скачиваются автоматически при первом запуске в папку `weights/`. Модель можно сменить параметром `--model`.

**Лицензия.** Библиотека Ultralytics распространяется под AGPL-3.0 (есть также коммерческая лицензия).

## Датасет

**COCO val2017** — 5000 изображений, 80 классов, стандартный набор для оценки детекторов. Модели обучены на train2017, поэтому val2017 для них новый.

- Для оценки используется **случайная выборка из 500 изображений** (seed = 42, воспроизводима).
- Аннотации: `instances_val2017.json`; изображения скачиваются скриптом `download_coco_val.py`.
- **Важно:** mAP считается на отдельных изображениях, а не на видео. Размеченных видео у меня не было, поэтому качество «на видео» оценивается косвенно: по скорости обработки, статистике детекций и просмотру результата.
- Для демонстрации используется видео `my_video.mov`: съёмка с высоты автомобильной встречи на парковке, 3840×2160 (4K), ~60 кадров/с, 1766 кадров (~29.5 с). Много людей и машин, часть объектов далеко от камеры. _Источник видео: взято на сайте Pexels

## Метрики

- **AP@[.5:.95]** (основная метрика COCO), **AP50**, **AP75**, AP по размерам объектов (small / medium / large), AR, **AP по классам**.
- **Скорость:** мс на изображение, число параметров модели.
- **На видео:** кадров в секунду при обработке, во сколько раз быстрее или медленнее реального времени, число детекций по классам, максимум объектов класса в одном кадре.
- Сравнение моделей `yolo11n` и `yolo11s` по качеству и скорости.

## Установка и запуск

```bash
cd video
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Обработка видео (положите видео в папку `videos/`):

```bash
python detector.py videos/clip.mp4
python detector.py videos/clip.mp4 --model yolo11s.pt --conf 0.4
python detector.py videos/clip.mp4 --max-frames 100     # быстрая проверка
```

Результаты появятся в `results/`: `clip_detected.mp4`, `clip_detections.csv`, `clip_summary.json`.

Оценка качества (mAP):

```bash
python download_coco_val.py                          # аннотации (~240 МБ, один раз) + 500 изображений (~80 МБ)
python evaluate.py --models yolo11n.pt yolo11s.pt
```

Использование в коде:

```python
from detector import detect_frame, process_video
detect_frame(frame)                       # список {label, confidence, box} для одного кадра
process_video("videos/clip.mp4")          # видео с рамками + сводка
```

## Результаты

Устройство: Mac на Apple M1 (`mps`). Все цифры из `results/metrics_*.json`, `results/comparison.csv`, `results/my_video_summary.json`.

### Качество на COCO val2017 (случайные 500 изображений)

| Модель | AP@[.5:.95] | AP50 | AP75 | AP small | AP medium | AP large | мс/изобр.* | Параметров |
|---|---|---|---|---|---|---|---|---|
| **yolo11n** | **0.415** | 0.571 | 0.453 | 0.226 | 0.420 | 0.610 | 35.1 | 2.6 млн |
| yolo11s | 0.484 | 0.653 | 0.528 | 0.310 | 0.524 | 0.680 | 47.2 | 9.5 млн |

\* Скорость измерена в `evaluate.py` с порогом уверенности 0.001 (стандартная настройка для расчёта mAP), поэтому постобработка тяжелее, чем при обработке видео; сравнивать эти значения с цифрами для видео нельзя.

**Критерии из ТЗ выполнены:** AP yolo11n = 0.415 ≥ 0.30, скорость на видео 13 кадров/с ≥ 5 кадров/с.

**Для справки:** авторы моделей публикуют AP 39.5 (yolo11n) и 47.0 (yolo11s) на полном val2017 при размере входа 640. Наши значения на 2.0 и 1.4 пункта выше. Это ожидаемо для небольшой случайной выборки из 500 изображений (доверительные интервалы для AP мы не считали), поэтому наши цифры стоит читать как подтверждение того, что модели работают так, как заявлено, а не как точную оценку.

**Сравнение моделей.** yolo11s точнее на 0.069 AP (+17%), но в 3.6 раза больше по числу параметров и на ~34% медленнее в наших замерах. Выигрыш неравномерен по размеру объектов: AP small вырос на 0.084 (+37%), medium на 0.104 (+25%), large на 0.069 (+11%). То есть более крупная модель прежде всего лучше находит мелкие и средние объекты. Для обработки видео на ноутбуке разумным выбором остаётся yolo11n (быстрее), а yolo11s стоит брать, когда важны далёкие объекты.

**AP по классам** (`results/per_class_ap_*.csv`). Хуже всего обе модели справляются с мелкими и тонкими предметами: у yolo11n самые низкие значения у `spoon` (0.08), `remote` (0.13), `backpack` и `handbag` (по 0.14), `boat` (0.15); у yolo11s у `backpack` (0.20), `knife` (0.21), `tie`, `book` и `donut` (по 0.23). Лучшие классы с достаточным числом объектов — `giraffe`, `refrigerator`, `laptop`, `fire hydrant` (AP 0.8 и выше). Значение `toaster = 1.00` статистического смысла не имеет: в выборке всего один такой объект, а для 11 классов в выборке меньше 10 объектов, поэтому AP по ним очень шумный.

### Анализ результатов на видео

Анализ основан на просмотре пяти кадров из разных моментов видео.

1. **Близкие и крупные объекты находятся уверенно.** Машины на переднем плане получают уверенность 0.8–0.93, люди 0.7–0.91, в том числе при необычном ракурсе сверху.
2. **Далёкие мелкие объекты теряются.** На кадрах 1–3 группы людей и машины на заднем плане (на расстоянии, где человек занимает несколько десятков пикселей) почти не получают рамок, а найденные далёкие объекты имеют низкую уверенность (0.25–0.35). Это согласуется с метриками на COCO: AP small у yolo11n в 2.7 раза ниже, чем AP large (0.226 против 0.610), и yolo11s справляется с мелкими объектами заметно лучше (0.310). Дополнительная причина в том, что кадр 4K сжимается до входа модели 640 пикселей (примерно в 6 раз), и далёкие объекты становятся совсем маленькими; увеличение `--imgsz` (например, до 1280) должно помочь ценой скорости, но мы этого не проверяли.
3. **Плотные группы.** В толпе рамки сильно перекрываются, часть людей, стоящих вплотную, объединяется или теряется; подписи на рамках накладываются друг на друга и становятся нечитаемыми.
4. **Пропуски и частично скрытые объекты.** На кадре 5 человек, сидящий в складном кресле рядом с оранжевой машиной, насколько видно на кадре, не получил отдельной рамки; человек у нижнего края кадра, видимый лишь частично, тоже не найден.
5. **Редкие классы вероятно содержат ложные срабатывания.** Классы `dog` (20 детекций), `umbrella` (12), `suitcase` (8), `skateboard` (47) встречаются лишь на единичных кадрах и, скорее всего, являются случайными срабатываниями на фоне; `stop sign` (19) на кадрах действительно виден, а `truck` (214) и `backpack` (32) выглядят правдоподобно (например, белые пикапы). Без ручной проверки всех кадров точно сказать нельзя; повышение порога `--conf` (например, до 0.4) убирает такие слабые срабатывания ценой потери части далёких объектов.

## Ограничения

- Метрики качества получены на отдельных изображениях COCO, а не на размеченном видео.
- Детектор работает покадрово, без отслеживания: один и тот же объект в разных кадрах считается заново, и `detections_total` — это число детекций, а не число уникальных объектов (для подсчёта уникальных объектов нужен трекинг, например `model.track` в Ultralytics).
- Известны только 80 классов COCO; специфические объекты не распознаются без дообучения.
- Мелкие, размытые и частично закрытые объекты находятся хуже.
