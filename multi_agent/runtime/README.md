# Локальный запуск LLM

Движок и веса хранятся в `.cache/`, в Git они не входят. Для macOS ARM64:

```bash
python -m multi_agent.runtime.setup
python -m multi_agent.runtime.setup --verify-only
python -m multi_agent.benchmark_models
```

Загрузка занимает около 4,2 GB. В `models.json` закреплены ревизии моделей,
размеры и SHA256. Повторная загрузка проверяет SHA256. Архив llama.cpp тоже
проверяется по хешу официального релиза. Большие файлы скачиваются только
командой `setup`; во время работы агента доступа в интернет нет.

Используется llama.cpp `b12359`, commit
`b1b770d90d94cad9e9ea5b993bdbc383a522fb28`, опубликованный 13 ноября 2026 года.
Выбор проверен 17 ноября 2026 года. Взята готовая сборка под Apple Silicon,
без установки системного сервиса. Для другой ОС нужен свой `llama-server`
через переменную `LLAMA_SERVER`; автоматическая загрузка движка сейчас
поддерживает только macOS ARM64. На другой ОС веса можно скачать командой
`python -m multi_agent.runtime.setup --skip-engine`.

Процесс слушает `127.0.0.1:18081`, Web UI отключен. Клиент отключает proxy из
окружения. Запросы выполняются последовательно: при смене роли предыдущий
сервер останавливается и загружается следующая модель. Это экономит RAM,
но увеличивает задержку. CPU имеет четыре рабочих потока, контекст ограничен
4096 токенами. CPU задается явно: `--device none --n-gpu-layers 0
--no-kv-offload --no-op-offload --fit off`. Одного `--n-gpu-layers 0`
недостаточно: другие операции и KV cache могут обращаться к Metal.
В итоговом эксперименте Metal отключен, поэтому результаты не
показывают максимальную скорость ноутбука. `cold_load_s` означает первый
запуск процесса модели в серии; файловый кеш ОС перед ним не очищается.
Benchmark использует отдельный
port `18082`, но для сравнимого замера его лучше запускать без параллельной
нагрузки.

Planner использует Qwen3.5-0.8B Q8_0: маленькая модель выбирает инструмент и
параметры. Writer использует Qwen3.5-2B Q4_K_M: большая модель пишет короткие
объяснения, а квантизация уменьшает файл весов. Validator использует
SmolLM3-3B Q4_K_M другого семейства. Отдельное семейство уменьшает зависимость
от одного генератора, но не дает независимости ошибок и не заменяет проверки
ID и схемы в Python. Конфигурация запрещает назначать валидатору семейство
автора или планировщика.

Сервер ограничивает выход JSON Schema. Это снижает число ошибок формата,
но не доказывает правильность содержания. Для этого в сравнении отдельно
проверяются выбор инструмента, значения полей, ID и решения судьи. Сырые
ответы сохраняются в `results/model_comparison.json`. Метрика writer в этом
наборе проверяет порядок ID и непустую причину, поэтому качество формулировок
нужно дополнительно смотреть в сырых ответах и системных evals.
