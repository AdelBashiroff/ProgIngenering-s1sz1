# Мультиагентный помощник по фильмам

Помощник работает с MovieLens 100K: выбирает рекомендации, показывает историю,
ищет названия и сравнивает item-CF с LightGCN. Данные берутся из инструментов,
а LLM разбирают запрос, выбирают фильмы и проверяют объяснения.

## ТЗ

Вход: русский запрос до 1500 символов и числовой ID пользователя. Выход: JSON
со статусом, ID, точными названиями, жанрами и короткими причинами выбора.
За один запрос выдаётся до пяти фильмов. Запросы об актуальных сеансах и стримингах
не поддерживаются: MovieLens 100K содержит старый каталог, а доступа в интернет нет.

Планировщик Qwen3.5-0.8B выбирает разрешённый инструмент и его параметры.
Qwen3.5-2B Q4 пишет ответ по результату инструмента. SmolLM3-3B Q4 проверяет
обоснование. Валидатор относится к другому семейству; это проверяется при старте.
LangGraph соединяет роли в один граф. Код дополнительно проверяет ID, повторы и
число фильмов. После отказа допускается одна доработка; затем ответ блокируется.
До tools небольшой словарный разбор уточняет явно названные жанры, запреты и
количество. Он исправляет потерянные ограничения слабой LLM, не меняя выбранный
инструмент или метод. Сложные отрицания и цитаты этот разбор может понять неверно.

Рабочая трактовка неоднозначного пункта «Jev-like Model» в задании —
LLM-as-a-Judge. Проверяющий агент реализует эту роль. Отдельной технологии с
выдуманной расшифровкой здесь нет.

## Установка

Основной проверенный вариант — macOS ARM64, Python 3.11. Для LLM нужно около
4,2 GB весов на диске. В один момент загружена одна модель. API-ключи не нужны.

```bash
source .venv/bin/activate
pip install -r multi_agent/requirements.txt
python -m recsys.download_data
python -m recsys.evaluate_advanced
python -m multi_agent.runtime.setup
python -m multi_agent.runtime.setup --verify-only
```

Модели, revisions, SHA256 и параметры находятся в [models.json](models.json).
Подробности движка: [runtime](runtime/README.md). Загрузка выполняется отдельно,
до изоляции. Система во время ответа использует только loopback.

## Запуск в изоляции

```bash
python -m multi_agent.sandbox --check
python -m multi_agent.sandbox --directory multi_agent/var/demo -- \
  -m multi_agent --directory multi_agent/var/demo ask \
  'Посоветуй 3 комедии без ужасов' --user 1
```

На этом Mac используется Seatbelt `sandbox-exec`: разрешено чтение исходников,
каталога, библиотек и весов; запись только в выбранный runtime; сеть только
localhost:18081. Дочерний llama-server наследует ограничения. Python исполняет
код приложения, но у LLM нет инструмента запуска кода. Запуск без sandbox для
отладки: `python -m multi_agent ask 'Посоветуй 2 драмы' --user 42`.

Seatbelt не создаёт отдельное ядро, не устанавливает жёсткие квоты RAM/CPU и
помечен Apple как deprecated. Это проверенная локальная изоляция для учебного
проекта. Сравнение VM, MicroVM, контейнеров и других sandbox дано в
[обосновании](docs/research.md). На другой ОС этот launcher завершится ошибкой,
а не незаметно запустит агента без ограничений.

## Память

```bash
python -m multi_agent profile --user 1 --prefer Comedy Drama --avoid Horror
python -m multi_agent forget --user 1
```

Три слоя: состояние одного графа в RAM, SQLite-кеш на 1 час, явные предпочтения
на 30 дней. Предпочтения меняются только этой командой. Ключ кеша включает версию
данных, checkpoint и профиль. После обновления данных процесс нужно перезапустить.
Подробности: [MEMORY.md](MEMORY.md). Команды используют свой `--directory`;
чтобы разделять память с demo, укажите `--directory multi_agent/var/demo`.

Траектории содержат текст запроса и ID пользователя. `forget` удаляет профиль,
метаданные запусков и кеш; JSONL очищается отдельно по сроку хранения монитором.
Версия рассчитана на одного локального оператора, аутентификации здесь нет.

## Проверки и метрики

```bash
python -m pytest -q
python -m multi_agent.benchmark_models
python -m multi_agent.sandbox --directory multi_agent/var/eval -- \
  -m multi_agent.evaluate --directory multi_agent/var/eval \
  --output multi_agent/var/eval/system_evaluation.json
python -m multi_agent.monitor --directory multi_agent/var/eval --once
python -m multi_agent.monitor --directory multi_agent/var/eval --port 9098
```

Последняя команда непрерывно проверяет телеметрию и публикует `/metrics` на
127.0.0.1:9098. Логи и траектории находятся в выбранной папке: `spans.jsonl`
(OTel spans с trace ID), `trajectories.jsonl` (планы, инструменты, ответы),
`metrics.prom` (Prometheus), `alerts.jsonl` (локальные предупреждения).
Завершившийся с ошибкой или отказом run создаёт алерт; время больше 120 с — тоже.
Монитор предупреждает об отсутствии свежей телеметрии. После перезапуска процесса
счётчики метрик начинаются заново. У правил Prometheus [alerts.yml](monitoring/alerts.yml)
есть отдельная конфигурация scrape; внешний Prometheus и Alertmanager не являются
обязательными сервисами и их запуск не выдаётся за выполненный.

Испытания трёх моделей используют 10 одинаковых задач: routing, выбор ID и
проверку ошибочных ответов. Schema-constrained decoding помогает формату JSON,
поэтому корректная схема не считается доказательством интеллекта модели.
End-to-end проверка использует 6 запросов: жанры, GNN, новый пользователь,
история, сравнение и вложенная инструкция. Метрика grounding проверяет ID
каталога; проверка смысла причины остаётся задачей LLM-судьи. Unit tests с
заглушками проверяют граф и не входят в реальные LLM-результаты.
Эти шесть сценариев используются при разработке и повторной проверке исправлений.
Это regression suite, а не независимый тест на новых пользовательских запросах.
Benchmark трёх LLM измеряет их сырые ответы без словарного исправления планов.

Файлы результатов: [results](results/). CTR, время просмотра и удержание
требуют настоящих пользователей и A/B-теста; здесь этих измерений нет.
